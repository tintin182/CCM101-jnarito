# ☁️ Mission Reflection

Writing a docker-compose.yml file makes a cloud engineer's job easier because it organizes all required configurations in one file. Instead of manually typing multiple commands for each container, engineers can define the application structure once and deploy it whenever needed. This reduces errors, saves time, and makes the deployment process easier to manage.

A YAML file requires proper formatting, especially with spacing and indentation. If an incorrect indentation is used, such as using a Tab instead of Spaces, Docker Compose may fail to read the configuration file. This prevents the containers from starting properly. Through this activity, I learned that small formatting mistakes can affect the entire deployment process.

Environment variables such as MYSQL_PASSWORD were used to provide important settings for the containers. They allow the application and database to communicate correctly while keeping configuration values organized. Using environment variables also makes it easier to modify settings without changing the main application structure.

Deploying a fully functional cloud storage system like Nextcloud in only a few minutes was a valuable experience. It showed me how automation can simplify complex deployment tasks. Instead of manually installing each component, Docker Compose handled the setup of Nextcloud and MariaDB through a single configuration file.

Since Mission 1, my understanding of Cloud Computing has improved significantly. Before, I mainly viewed cloud computing as accessing services through the internet. After completing these activities, I now understand that cloud computing also involves infrastructure management, automation, containers, and proper system design.

This laboratory helped me understand the role of cloud engineers in building and maintaining applications. Docker Compose demonstrated how different services can work together efficiently, and it gave me more confidence in managing cloud-based deployments.
