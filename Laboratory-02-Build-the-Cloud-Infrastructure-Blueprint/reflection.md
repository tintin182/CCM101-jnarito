# Laboratory 02 — Reflection

This laboratory gave me a better understanding of how the different parts of cloud infrastructure work together. Among the components I investigated, I consider compute resources to be one of the most important because they provide the processing power needed to run applications, services, and commands. However, the activity also showed me that compute does not work alone. Storage, networking, and the operating system all contribute to creating a working environment where applications and services can operate properly.

Working with the KillerCoda Linux environment helped me understand how Linux supports cloud computing in a practical way. Instead of only reading about system resources, I was able to investigate them directly using Linux commands. I checked the operating system, kernel, CPU, memory, storage, mounted filesystems, hostname, and IP addresses. Seeing this information through the terminal made the concepts easier to understand because I could connect what I learned in the module to an actual cloud-based environment.

I also realized why technical documentation is important before deploying infrastructure. Documentation provides a clear record of the resources that were investigated, the decisions that were made, and how the different components relate to one another. It also makes technical work easier for other people to understand, review, and maintain.

Throughout the laboratory, I improved my skills in Linux system investigation, cloud infrastructure analysis, Markdown documentation, Git and GitHub, and cloud architecture design using Adobe XD. Creating the architecture diagram also helped me think about how the different infrastructure components connect rather than simply treating them as separate resources.

Overall, this laboratory improved my GitHub portfolio by adding organized and documented cloud computing work. More importantly, it gave me practical experience that goes beyond simply knowing cloud computing concepts. I was able to investigate a real Linux environment, document my findings, compare cloud infrastructure services, and create a visual representation of a cloud architecture. This made the laboratory a useful step in building both my technical skills and my portfolio.
